# ForgeAI - the agent that builds agents

Give it a one-paragraph brief and a folder of documents. It produces a tested agent definition and an
honest quality report. Everything runs locally on Ollama.

## Setup

```
python -m pip install -r requirements.txt
ollama pull mistral
ollama pull nomic-embed-text      # optional; BM25 is used without it
```

## Use

Web UI (build, results, chat):

```
python -m streamlit run app.py
```

Command line:

```
python -m forgeai run --brief-file demos/hr/brief.txt --docs demos/hr/docs --out demos/hr/run --name hr_assistant
python -m runner.chat demos/hr/run/agent_definition.yaml --docs demos/hr/docs --debug
python -m forgeai regress --run demos/hr/run --docs path/to/changed_docs --out runs/hr_regression
```

| Flag | Meaning |
|---|---|
| `--fast` | 20 cases, 1 optimizer iteration |
| `--interactive` | answer the intake questions yourself (default: unattended) |
| `--requirements-only` / `--requirements FILE` | human checkpoint: review requirements, then continue |
| `--checkpoint` | same, in one CLI session |
| `--tournament 3` | try 3 candidate system prompts, the eval set picks one |
| `--budget-seconds N` | no new optimizer iteration after N seconds |
| `--model`, `--judge-model` | choose Ollama models |

## How it works

| Stage | File | Notes |
|---|---|---|
| Intake (max 5 questions) | `forgeai/intake.py` | writes requirements.json / .md |
| Groundability guard | `forgeai/guard.py` | word overlap + model verdict; unsupported topics become refusals |
| Generator | `forgeai/generator.py` | declarative YAML definition |
| Tools | `forgeai/tools/registry.py` | attached only if the model asks AND a rule agrees |
| Eval generator | `forgeai/evalgen.py` | key facts must appear verbatim in the source |
| Judge | `forgeai/judge.py` | rules first, model only when rules are unsure |
| Critic-optimizer | `forgeai/optimizer.py` | max 3 iterations; a patch is kept only if the score rises |
| Report | `forgeai/report.py` | what still fails and why |
| Runtime / runner | `forgeai/agent.py`, `runner/chat.py` | loads any definition |

All generation prompts are in `prompts/`; demo document synthesis prompts are in `demos/synth_prompts/`
(`demos/synth.py` builds the documents; the spares catalogue CSV is generated by seeded code).

## Artifacts of a run

`requirements.{json,md}`, `agent_definition.yaml` (shipped) plus per-iteration versions, `evalset.jsonl`,
`iteration_N_results.jsonl`, `final_results.jsonl`, `iterations.json` (change log), `scorecard.{json,md}`,
`report.md`, `usage.json`, `run_meta.json`.

## Tests

```
python -m pytest -q tests -p no:cacheprovider
```

`tests/test_pipeline_fake.py` runs the whole pipeline with a scripted fake model. It checks wiring only
and says nothing about model quality.

## Known limits

- Slow without a GPU: the first full HR run logged about 6.7 hours of model time on `mistral`, CPU only.
- Fact matching is lexical, so correct paraphrases can be marked wrong.
- Agent and judge use the same model by default (possible self-preference).
- The optimizer is tuned and scored on the same eval set; there is no held-out set.
- Intake questions in unattended mode are answered with assumed defaults, listed in the requirements.
- Not done: hand-written human baseline, public hosting. The app needs a local Ollama server, so free
  hosting tiers would need a different model backend.
